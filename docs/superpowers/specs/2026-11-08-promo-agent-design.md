# 홍보글 에이전트 설계 (2026-11-08)

사장님이 휴대폰으로 사진 몇 장과 한 줄 메모를 올리면, 사장님 말투로 네이버 블로그 · 인스타그램 · 당근 · 네이버 플레이스 초안 4개를 만들어 주는 웹 앱.

## 1. 왜

- 사장님 인터뷰에서 "사라졌으면 하는 일"과 "미루는 일" 둘 다 **글쓰기**. 블로그 글 하나에 1~2시간, 사진 고르기가 제일 오래 걸림.
- 같은 내용을 네 채널에 **말투만 바꿔** 직접 올림. 채널별 말투를 기억해 두는 게 부담.
- ChatGPT·Claude를 써 봤지만 **말투가 AI 같아서** 그만둠. → 이 에이전트의 핵심 가치는 "사장님이 쓴 것 같은 말투".
- 공개 블로그(`blog.naver.com/stone_bridge_`)에 사장님이 직접 쓴 글이 50개 넘게 있음. 이게 말투 학습 재료.

## 2. 성공 기준

- 사장님이 첫 주제 **"크리스마스 마카롱 주문 안내"**를 이 앱으로 만들어 네 채널에 올린다.
- 앱을 열어서 네 채널 게시까지 **20분 이내** (지금은 블로그 하나에 1~2시간).
- 사장님이 블로그 초안을 보고 "내가 쓴 것 같다"고 말한다. 확정본과 초안의 차이(얼마나 고쳤나)를 기록해 측정한다.

## 3. 범위

### v1 = Day 4 제출 (2026-11-11 06:00 KST)

1. 사장님 전용 로그인 (비밀번호 하나).
2. 새 글: 사진 최대 8장 + 한 줄 메모 + 글 종류(**단체 주문 사례 / 상품·시즌 안내 / 기타**) + "개인 고객" 체크 + "가격표 붙이기" 체크.
3. 생성: 네 채널 초안을 한 번에. 생성 중 화면을 닫아도 계속 진행.
4. 결과 화면: 채널 탭, 고칠 수 있는 글 상자, 채널별 **복사** 버튼, 채널별 **다시 쓰기**(한 줄 지시 가능, 예: "더 짧게"), **확정** 버튼.
5. 블로그 초안에는 `[사진 3]` 같은 사진 위치 표시. 화면에 같은 번호를 붙인 사진 줄을 보여 준다 (네이버 에디터는 붙여넣기로 사진이 안 들어가서 사장님이 직접 넣음).
6. 설정 화면: 고정 꼬리말(채널별), 가격표, 말투 규칙, 예시 글 목록(켜기/끄기, 블로그에서 다시 가져오기).
7. 지난 글 목록.

### v2 (11/16 챌린지 끝까지, 순서대로)

1. 카카오톡 "나에게 보내기" 알림: 매월 글 올릴 때 알림, 매일 23:20 발주 알림. (7장 참고)
2. 사진 고르기: 사진을 한꺼번에 많이 올리면 "딱 봤을 때 내용이 전달되는" 8장을 AI가 먼저 골라 줌. 사장님이 아직 사진 묶음이 없어 v1에서는 사장님이 고른 사진만 받음.
3. 인스타그램 자동 게시 (공식 Graph API 있음. 비즈니스/크리에이터 계정 + 페이스북 페이지 연결 필요).
4. 스톤테이블(케이터링) 브랜드 분리: 설정·예시를 브랜드별로.

### 하지 않는 것

- 네이버 블로그·당근·네이버 플레이스 자동 게시: 공식 쓰기 API 없음. 복사 버튼이 정답이다.
- 카톡 안에서 답장으로 고치기: 카카오톡 채널 챗봇을 따로 신청해야 함. 웹 화면에서 고친다.

### 실패로 치는 것 (동작해도 실패)

- 말투가 AI 같다: 😊🎉 같은 일반 이모지, "~해 보세요!" 같은 광고 문구, 긴 문장, 과한 칭찬.
- **사실을 지어낸다**: 가격·수량·날짜·기관 이름 중 메모·가격표에 없는 값이 글에 들어간다.
- 개인 고객 이름이나 연락처가 글에 노출된다. (기관·관공서 이름은 써도 됨, 개인은 익명)
- 사장님 원본 자료(사진, 블로그 원문, 꼬리말, 가격)가 **공개 저장소**에 들어간다.
- 휴대폰 한 손으로 못 쓴다.

## 4. 제약

- **공개 저장소.** 코드만 올린다. 사장님 자료는 전부 D1·R2에만, 시드는 `private/`(gitignore)에서. 저장소에는 가짜 예시 시드만.
- 스택은 cafe-manager와 같게: React Router 8 + Cloudflare Workers + D1 + R2 + Tailwind/shadcn. 나중에 cafe-manager로 합칠 예정이므로 홍보 기능 코드는 한 폴더(`app/promo/`)에 모은다.
- 사용자는 사장님 한 명. 휴대폰(iPhone 추정) 웹 브라우저.
- 비밀값(Claude API 키 등)은 Cloudflare secret으로만.
- 비용: 글 한 번에 입력 약 3만 토큰 + 출력 약 8천 토큰 ≈ **$0.3**. 월 1~2회라 문제없음.
- Cloudflare 요금제: Workflows는 무료 요금제에서도 됨(인스턴스당 1,024단계, 단계 실행 시간 제한 없음). 단 **무료 요금제 CPU 10ms**가 Claude 스트리밍 응답 파싱에서 걸릴 수 있다. 배포 후 `exceededCpu`가 보이면 Workers Paid($5/월)로 올린다.

## 5. 결정된 것

### 5.1 화면 흐름

```
로그인 → 글 목록 ─ [새 글] → 사진·메모 입력 → [초안 만들기]
                                          ↓
                              생성 중 (닫아도 됨, 다시 열면 이어서)
                                          ↓
         결과: [블로그][인스타][당근][플레이스] 탭
               제목/본문 편집 · 복사 · 다시 쓰기 · 확정
               블로그 탭: 번호 붙은 사진 줄
```

### 5.2 생성 방식

- 모델 `claude-opus-5-5`, `output_config.effort: "high"` 명시 (기본값이 medium). 스트리밍 + `finalMessage()`.
- **한 번의 호출로 네 채널** 모두 생성 (사진을 한 번만 보게). 응답 형식은 `output_config.format` JSON 스키마로 강제:
  ```
  { blog:      { title, body },
    instagram: { body, hashtags[] },
    daangn:    { title, body },
    place:     { body },
    photos:    [{ n, note }] }   // 블로그 사진 순서와 한 줄 설명
  ```
  (Opus 5.5는 prefill, `tool_choice: any/tool` 불가 → 구조화 출력으로만.)
- 거절 대비 `fallbacks: "default"` + 베타 헤더 `server-side-fallback-2026-07-01`.
- 시스템 프롬프트(캐시 대상, `cache_control`): 말투 규칙 + 채널 규칙 + 예시 글. 요청마다 바뀌는 것(메모, 사진, 체크값)은 그 뒤 user 메시지에.
- 다시 쓰기: 해당 채널만, 현재 초안 + 사장님 지시를 넣어 한 번 더 호출.
- **화면을 닫아도 생성이 끝나야 한다.** 휴대폰 화면이 꺼지면 HTTP 요청이 끊기고, Workers는 끊긴 요청을 취소한다. → 생성은 **Cloudflare Workflows**로 돌린다(단계별 재시도, 요청과 분리). 화면은 2초마다 상태를 확인.

### 5.3 사진

- 휴대폰에서 고른 사진을 브라우저에서 **긴 변 1600px JPEG로 줄여서** 올린다 (iPhone HEIC 대응, Claude는 1568px 넘으면 어차피 줄임, 장당 5MB 제한).
- R2 비공개 버킷에 저장. 앱 화면에서는 로그인 확인 후 보여 준다.
- Claude에는 **서명된 짧은 수명 URL**(10분, HMAC)로 넘긴다 (`image.source.type: "url"`). Worker가 사진을 base64로 바꾸지 않아도 돼 CPU·요청 크기가 줄어든다.

### 5.4 고정 문구는 AI가 쓰지 않는다

- 꼬리말(배송 정책, 주소, 영업시간, 연락처)과 가격표는 **설정에 저장된 문구를 코드가 그대로 붙인다.** 틀린 가격·번호가 나갈 수 없게.
- 채널별 꼬리말: 블로그 = 전체, 인스타·당근 = 짧은 판(주소·영업시간·주문 방법), 플레이스 = 없음(플레이스에 이미 정보가 있음). *(내 판단, 사장님 확인 필요)*
- 가격표는 "가격표 붙이기" 체크 시 블로그·당근에만 붙인다. *(내 판단)*

### 5.5 사실 확인 (지어내기 방지)

- 프롬프트: "메모·사진·가격표에 없는 숫자, 날짜, 이름은 쓰지 않는다. 모르면 비워 둔다."
- 코드 검사: 초안의 숫자(가격·수량·날짜)가 메모 + 가격표 + 꼬리말에 없으면 화면에 **노란 표시**. "개인 고객" 체크면 사람 이름처럼 보이는 말도 표시.

### 5.6 말투 재료 (예시 글)

- `scripts/import-blog.ts` (로컬 실행): 블로그 RSS(`rss.blog.naver.com/stone_bridge_.xml`) → 모바일 글 화면에서 본문과 사진 위치 추출 → `private/examples.json` → D1 `examples` 표에 시드. 추출 방식은 확인 완료(`se-text-paragraph` 문단, `se-image-resource` 사진).
- 글 종류 분류: 제목이 `[장소] ... 단체 주문` 꼴이면 사례, 그 외 상품·시즌. 설정 화면에서 고칠 수 있게.
- 생성 시 채널마다 같은 종류의 예시 2~3개를 넣는다. 사장님이 **확정한 글은 새 예시로 저장**되어 다음부터 우선 쓰인다 (쓸수록 사장님 말투에 가까워짐).
- 인스타·당근·플레이스는 사장님 예시가 아직 없다. 블로그 말투 + 아래 채널 규칙으로 시작하고, 확정본이 쌓이면 그걸 예시로 쓴다.

### 5.7 말투·채널 규칙 (시스템 프롬프트에 넣을 것)

공통 (사장님 블로그 분석에서):
- 한 줄에 한 문장, 블로그는 문단 사이 빈 줄.
- "~요 / ~습니다" 섞기, 느낌표 많이.
- 일반 이모지 대신 유니코드 얼굴 문자를 문장 끝에: `(˶˙๏˙˶)♡` `♡ ˙ᵕ˙ ♡` `𐔌՞. .՞𐦯` `˶ˆᗜˆ˵` `｡·͜·｡` `⸜( ˙ ˘ ˙)⸝♡`.
- 1인칭 "저희", "스톤브릿지가". 가벼운 농담 한 줄 허용 ("살짝의 네고도 ... ㅎㅎ").
- 판매 경험을 근거로 든다.

블로그 (사장님 글 구조 그대로):
- 제목: 사례 = `[장소] 상품 수량 단체 주문 | 키워드 | 키워드`, 상품 = `스톤브릿지 + 시즌 + 상품명`.
- 순서: 여는 줄(시기·상황) → 주문 사례 → 상품 디테일(맛, 포장, 스티커) → 정성 문장 → (가격표) → 주문 안내 → (꼬리말). 1,000~1,500자, 얼굴 문자 4~5개.

인스타 / 당근 / 플레이스 *(내 판단, 사장님 피드백으로 고칠 것)*:
- 인스타: 첫 줄에 핵심, 300~600자, 얼굴 문자 2~3개, 해시태그 10~15개(지역 + 상품 + 용도).
- 당근 (비즈프로필 소식): 동네 이웃에게 말하듯, 300~500자, 가격·주문 방법 분명히, 해시태그 없음.
- 플레이스 소식: 150~300자, 핵심 정보만.

## 7. 카카오 "나에게 보내기" (v2) — 확인한 사실과 남은 위험

확인함 (developers.kakao.com, 2026-11-08):
- 나에게 보내기는 **발송 건수 제한 없음** (앱 검수 전후 모두). 친구에게 보내기만 하루 30건 제한.
- 액세스 토큰 6시간, 리프레시 토큰 2개월. 만료 1개월 전부터 갱신 가능하고, **갱신하면 새 리프레시 토큰이 나오고 옛 것은 폐기** → 새 토큰을 D1에 바로 저장해야 함 (실패하면 사장님이 다시 로그인).
- 동의 항목: 카카오 로그인 > 동의항목 > 접근권한 > "카카오톡 메시지 전송".
- 예약: Workers Cron Trigger. 23:20 KST = **14:20 UTC** 매일, 월간 알림은 매월 정한 날.

남은 위험 (만들기 전에 확인):
- "카카오톡 메시지 전송" 동의 항목을 **비즈 앱 없이** 팀원이 아닌 사장님 계정에 켤 수 있는지: 문서에 없음 → Kakao Developers 콘솔에서 직접 확인.
- 카카오 문서는 이 API를 "사용자 간 상호작용" 용도로 설명하고, **서비스가 사용자에게 보내는 알림은 알림톡**을 쓰라고 함. 1인 자가용 알림은 회색지대. 막히면 대안: 웹 푸시(iOS 홈 화면 추가 필요) 또는 텔레그램 봇.
- v1은 카카오에 전혀 의존하지 않는다.

## 8. 만드는 사람에게 맡기는 것

- 화면 세부 디자인 (cafe-manager 컴포넌트·톤 재사용 권장).
- 프롬프트 문장 다듬기 (5.7 규칙은 지키되 표현은 자유).
- Workflows 단계 나누기, 재시도 횟수, 폴링 방식.
- 사진 줄이기 구현 (canvas / createImageBitmap).
- 예시 글 고르는 기준 세부 (최신순, 길이 등).
- 숫자 검사의 정규식 세부.
